# 16 型人格副本馆项目文档

> 项目定位：一个基于 16 型人格刻板印象与关系场景的娱乐向互动闯关网站。  
> 当前仓库状态：仓库目前暂无源码文件，因此本文档作为项目从 0 到 1 的产品说明、技术方案、内容体系与开发索引文档。

---

## 1. 项目概述

### 1.1 项目名称

暂定名称：**16 型人格副本馆**

可选名称：

- 人格副本馆
- 人格 Boss 挑战
- 关系死亡报告
- 你会死在第几关
- 16 型人格修罗场
- 人格关系挑战

### 1.2 一句话介绍

**用户选择一个人格 Boss，通过一系列关系场景选择题进行闯关，系统根据用户反应给出死亡报告、通关等级和可分享战绩卡。**

### 1.3 项目核心

本项目不是严肃心理测评，也不承诺提供真实关系建议，而是一个娱乐向互动内容产品。

核心体验是：

> 你以为你懂 TA，其实你第一关就死了。

项目通过 MBTI/16 型人格在互联网上形成的常见刻板印象，设计成不同主题的互动副本，让用户在选择题、死亡报告、通关结果和分享卡中获得娱乐、共鸣和转发欲。

### 1.4 项目目标

- 做一个好玩、上头、能转发的 16 型人格互动网站。
- 每个人格不只是换皮，而是有独立副本主题、语气、人设和死亡方式。
- 首期优先上线 4 个高传播人格副本，后续扩展到 16 个。
- 网站需要具备内容可配置能力，方便后期不断新增题目、人格和活动玩法。

## 2. 用户与使用场景

### 2.1 目标用户

主要用户：

- 喜欢 MBTI、星座、人格测试、恋爱测试的年轻用户；
- 喜欢在社交平台转发测试结果的人；
- 对亲密关系、暧昧、复合、聊天判断感兴趣的人；
- 喜欢“被说中”“破防”“哈哈哈哈这也太像了”的娱乐内容用户。

### 2.2 使用场景

典型场景：

1. 用户在社交平台刷到某个人格挑战视频；
2. 点击进入网站；
3. 在首页选择人格 Boss；
4. 进入挑战，完成 5-7 道选择题；
5. 中途失败，获得死亡报告；
6. 或者通关，获得通关报告；
7. 生成战绩卡，转发给朋友；
8. 朋友再选择自己或伴侣的人格进行挑战。

### 2.3 核心传播路径

项目的传播不是靠“准”，而是靠：

- 好笑；
- 刺痛；
- 像；
- 有梗；
- 可以转发给具体的人。

典型转发话术：

- “你快玩这个，你绝对死在第一关。”
- “这 INTJ 写得也太像你了。”
- “我不是在玩测试，我是在被系统审判。”
- “我死在第 2 关，你来试试。”

## 4. 核心玩法

### 4.1 基础流程

```text
进入首页
  ↓
选择人格 Boss
  ↓
进入副本介绍页
  ↓
开始挑战
  ↓
展示关系场景
  ↓
用户选择 1 个选项
  ↓
系统判断结果
  ↓
正确：进入下一关
错误：展示死亡报告
  ↓
生成结果卡
  ↓
用户分享或重新挑战
```

### 4.2 每关结构

每一关由以下内容组成：

- 关卡编号：第 1 关、第 2 关；
- 场景标题：例如“TA 说没事”；
- 聊天内容：模拟对话气泡；
- 问题：你会怎么回？
- 4 个选项：A/B/C/D；
- 正确答案或推荐答案；
- 错误答案对应死亡报告；
- 死亡率数据；
- 下一关入口。

### 4.3 失败机制

失败不叫“答错”，而叫“死亡”。

例如：

- 你死于第 1 关：解释成瘾；
- 你死于第 2 关：情绪逼供；
- 你死于第 3 关：冷处理反噬；
- 你死于第 4 关：证明欲过载；
- 你死于第 5 关：旧模式复发。

失败反馈要有强情绪，不要像普通测试结果。

错误示例：

> 你的选择不太合适，建议下次更温柔一点。

正确示例：

> 你以为你在解释，其实你又把重点放回了自己身上。TA 要的不是一份说明书，是一次被接住的感受。

### 4.4 通关机制

用户通关后生成通关报告：

- 通关人格；
- 用时；
- 死亡次数；
- 通关等级；
- 人格副本评语；
- 分享图。

通关等级示例：

- SSS：旧模式毁灭者；
- S：情绪接住大师；
- A：危险但能活；
- B：差点又犯病；
- C：建议重新做人；
- D：你只是侥幸没死。

## 5. 16 型人格副本设计

### 5.1 设计原则

每个人格必须有专属主题，不要全部叫“挽回挑战”。

INFJ 适合“挽回”，但其他人格要基于常见互联网印象做差异化设计。

每个人格需要包含：

- 人格代号；
- 副本名称；
- Boss 称号；
- 核心误区；
- 典型死亡方式；
- 语言风格；
- 挑战难度；
- 通关率；
- 平均死亡关卡。

### 5.2 首批推荐上线人格

建议首期先做 4 个：

1. INFJ：挽回 INFJ 挑战；
2. INTJ：破解 INTJ 防火墙；
3. INFP：修复 INFP 旧梦；
4. ENTP：别被 ENTP 反杀。

原因：

- INFJ：话题度最高，适合情绪深度；
- INTJ：冷感强，Boss 感强；
- INFP：破碎感强，用户共鸣强；
- ENTP：娱乐性强，适合反杀和吐槽。

## 8. 技术方案

### 8.1 推荐技术栈

第一版建议使用轻量前端栈：

- React
- Vite
- TypeScript
- Tailwind CSS
- Framer Motion
- Zustand 或 React Context
- html2canvas 或 satori，用于生成分享图

如果后续需要登录、数据统计、排行榜，可以引入：

- Supabase；
- PostgreSQL；
- Prisma；
- Next.js；
- Vercel。

### 8.2 第一版架构

第一版可以完全前端静态化。

```text
浏览器
  ↓
React 页面
  ↓
本地 TypeScript/JSON 内容配置
  ↓
答题状态管理
  ↓
结果计算
  ↓
生成分享卡
```

优点：

- 开发快；
- 部署简单；
- 不需要后端；
- 适合先验证内容传播。

缺点：

- 不能真实统计通关率；
- 数据容易被前端看到；
- 后续活动运营能力有限。

### 8.3 第二版架构

第二版可以加入后端统计。

```text
前端 React / Next.js
  ↓
API Route / Serverless Function
  ↓
Supabase / PostgreSQL
  ↓
记录挑战结果、死亡关卡、人格选择、分享次数
```

可以统计：

- 每个人格挑战次数；
- 每一关死亡人数；
- 每个选项选择比例；
- 分享转化率；
- 最高通关率人格；
- 最难人格副本。

## 10. 结果计算规则

### 10.1 简单模式

第一版可以使用简单规则：

- 每题只有 1 个推荐选项；
- 选错立即死亡；
- 选对进入下一关；
- 全部选对则通关。

### 10.2 进阶模式

后续可以加入隐藏分值：

```ts
export interface OptionScore {
  empathy: number;
  pressure: number;
  logic: number;
  control: number;
  selfFocus: number;
}
```

根据用户选择累计分数，最后生成不同报告。

例如：

- `pressure` 过高：情绪逼供型；
- `selfFocus` 过高：证明自己型；
- `control` 过高：关系管理型；
- `logic` 过高但 `empathy` 低：说明书型；
- `empathy` 高且 `pressure` 低：接住情绪型。

## 12. 内容写作规范

### 12.1 文案原则

项目文案要做到：

- 像：符合用户对人格的刻板印象；
- 狠：结果报告要有审判感；
- 好笑：不能太沉重，要有梗；
- 可转发：结果要让用户愿意发给朋友；
- 不装专业：明确娱乐向，不做医学或心理诊断。

### 12.2 死亡报告写法

公式：

```text
你以为【你的行为动机】，其实 TA 感受到的是【对方视角】。
你输给的不是【表面问题】，而是【深层旧模式】。
```

例子：

> 你以为你在解释，其实 TA 感受到的是你又把重点放回了自己身上。你输给的不是这句话，而是长期没人接住 TA 的感受。

### 12.3 副本名称写法

不要直接全部叫“挽回 XXX”。

命名公式：

```text
动词 + 人格核心意象
```

例如：

- 挽回 INFJ 挑战；
- 破解 INTJ 防火墙；
- 修复 INFP 旧梦；
- 唤醒 INTP 离线线程；
- 抓住 ENFP 的风；
- 别被 ENTP 反杀。

## 16. 风险与注意事项

### 16.1 内容风险

注意不要宣称：

- 可以真正挽回某个人；
- 可以准确判断人格；
- 可以提供专业心理建议；
- 可以替代真实沟通。

### 16.2 商标与专业性风险

建议使用“16 型人格”作为主表述，不要把项目包装成官方 MBTI 测试。

页面应加入娱乐免责声明。

### 16.3 用户体验风险

死亡报告要“狠”，但不能恶意攻击用户。

建议边界：

- 可以吐槽行为模式；
- 不要侮辱人格；
- 不要诱导极端关系行为；
- 不要制造真实焦虑。

## 17. 项目当前结论

当前仓库适合从以下方向开始：

1. 先做一个静态前端 MVP；
2. 优先完成 INFJ 副本；
3. 再扩展 INTJ、INFP、ENTP；
4. 核心竞争力放在内容质量，而不是复杂技术；
5. 所有题目、人格信息、死亡报告都应配置化；
6. 最终做成可持续扩展的 16 型人格娱乐互动网站。

一句话总结：

> 这不是一个严肃 MBTI 测评项目，而是一个“人格刻板印象 + 关系场景 + 游戏副本 + 死亡报告”的互动娱乐产品。
