# 副本软解锁与流量策略

> 目标：制造“内容有世界观、有稀缺感、有更新感”，但不做收费、不登录、不强制分享。

---

## 1. 核心判断

本项目不适合硬锁。

不建议做：

```text
分享给 3 个好友解锁
登录后解锁
每天只能玩 1 次
必须测完才能玩
必须看广告才能玩
```

原因：用户是来玩梗的，不是来完成任务的。第一口爽感还没吃到就被拦，很容易直接流失。

但也不建议 16 个副本全部直接铺开并全部可玩。

原因：

```text
全开放会像题库，不像副本。
全开放会降低稀缺感。
全开放会让用户没有游玩路径。
全开放会让内容显得廉价。
```

最终方案：

> 全站可见，但不是全站可玩；先给爽点，再给解锁感。

## 2. 当前实现

首页分为三层：

### 2.1 双入口

```text
我知道自己的类型 → 直接选择人格 Boss
我不知道自己的类型 → 先做前置测试
```

当前前置测试逻辑已在仓库中，但前端测试页还没有完整接入；首页先保留入口和说明。

### 2.2 已开放副本区

当前开放：

```text
INFJ：挽回 INFJ 挑战（样板副本）
INTJ：破解 INTJ 防火墙
INFP：修复 INFP 旧梦
ENTP：别被 ENTP 反杀
```

INFJ 是样板副本，拥有：

- 5 关连续剧情主线；
- 状态变量；
- 隐藏 flag；
- 多结局；
- 选择后反馈。

其他 3 个仍为基础玩法。

### 2.3 未开放档案区

剩下 12 个副本显示为“档案预告”。

用户能看到：

- 副本名；
- Boss 名；
- 简介；
- 难度；
- 平均死亡关卡；
- 预告标签；
- 想玩按钮。

点击“想玩这个”不会强制分享，也不会收费，只会在页面上显示“已记录你的呼声”。

这是一种轻量参与感。

## 3. 状态分类

人格卡片新增 `releaseStatus`。

```ts
type ReleaseStatus = 'sample' | 'open' | 'preview' | 'hidden';
```

含义：

| 状态 | 含义 | 用户感受 |
|---|---|---|
| sample | 样板副本 | 最高完成度，主推体验 |
| open | 已开放 | 可以直接开玩 |
| preview | 档案预告 | 可见但未完全开放 |
| hidden | 隐藏 Boss | 后期用于彩蛋 |

当前版本主要使用：

```text
sample：INFJ
open：INTJ / INFP / ENTP
preview：其他 12 型
```

---

## 4. 为什么这样比硬锁好

硬锁给用户的感觉是：

```text
你不能玩。
```

软解锁给用户的感觉是：

```text
这个世界还没完全展开。
```

二者差别非常大。

硬锁像限制功能。
软解锁像游戏内容。

---

## 5. 结果页回流

结果页新增“副本推荐已解锁”。

示例：

```text
挑战 INFJ 后推荐 INTJ。
原因：你刚经历了“感受被接住”的审判，下一站可以试试完全不同的冷启动系统。
```

这个不是强制解锁，而是结果后的自然回流。

用户玩完一个副本后，会有理由回大厅继续玩。

---

## 6. 完整死亡档案

INFJ 叙事副本的结果页现在会显示：

```text
完整死亡档案：已解锁
```

内容包括系统识别出的旧模式，例如：

- 证明欲偏高；
- 压迫感偏高；
- 边界尊重较好；
- 旧模式被识别；
- 信任修复中。

这比锁副本更高级。

用户不是为了“解锁内容”而做任务，而是因为自己已经玩完，所以自然想看：

```text
我到底怎么死的？
```

## 8. 最终原则

```text
不要为了限制而限制。
不要让用户觉得内容少。
不要强迫分享。
不要把娱乐产品做成任务系统。

让用户看到世界很大。
让用户先吃到爽点。
让结果页自然产生转发欲。
让未开放内容像档案，而不是缺功能。
```

一句话：

> 不锁门，但保留门后还有东西的感觉。
