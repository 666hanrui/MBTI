# 人格副本馆游戏设计圣经

> 目标：先把项目定调定下来。后续所有题目、剧情、视觉、交互和代码结构都围绕这份设计规则展开。

---

## 1. 核心判断

当前项目不能继续停留在“每关独立选择题”的层面。

如果每一道题之间没有关系，用户会很快感觉这是普通心理测试换皮：

```text
看场景 → 点选项 → 看解释 → 下一题
```

这种玩法短期能跑，但不够有心意，也不够上头。

真正要做的是：

```text
用户不是在答题，而是在推进一段关系脚本。
用户不是选答案，而是在暴露自己的旧模式。
每一次选择都应该被系统记住，并影响后面的称呼、反馈、死亡方式和结局。
```

一句话定调：

> 这是一个“有剧情记忆的人格关系副本”，不是一套孤立选择题。

---

## 2. 产品最终体验

用户进入网站后，应该感觉自己进入了一个人格 Boss 副本大厅。

每个副本都像一段被压缩成 5-7 分钟的关系剧本：

- 开场：TA 已经处在某种关系状态里；
- 第 1 关：用户触发旧模式；
- 第 2 关：系统开始识别用户惯性；
- 第 3 关：TA 的反应根据前面选择发生细微变化；
- 第 4 关：隐藏变量开始生效；
- 第 5 关：用户面对最终考验；
- 结局：死亡、残血存活、普通通关、隐藏通关。

用户玩完之后，不应该只记得“我选错了”。

用户应该记得：

> 我好像真的被这个副本审了一遍。

---

## 3. 核心调性

### 3.1 关键词

- 有梗；
- 毒舌；
- 像；
- 上头；
- 破防；
- 有细节；
- 有剧本感；
- 有被系统记住的感觉；
- 有“这个人格真的不一样”的差异感。

### 3.2 不能变成什么

不能变成：

- 严肃心理测试；
- AI 情感导师；
- 生硬说教；
- 每个人格只是换了名字；
- 每关之间没有联系；
- 错误反馈只有“你应该更温柔”；
- 页面像问卷星。

### 3.3 应该像什么

应该像：

- 人格主题短剧；
- 恋爱版 roguelike；
- 聊天模拟器；
- 关系死亡报告生成器；
- 带审判感的互动剧情游戏；
- 一个会记仇、会复盘、会吐槽用户的系统。

## 4. 世界观设定

### 4.1 副本大厅

首页不是“测试列表”，而是“副本大厅”。

用户选择的不是一个测评，而是一个人格 Boss。

首页文案方向：

> 16 型人格副本已开启。  
> 选择一个 Boss，看看你会死在第几关。

### 4.2 系统身份

系统不是中立裁判，而是一个“关系副本记录员”。

它会：

- 记录用户前面的选择；
- 识别用户的旧模式；
- 在后续关卡里阴阳怪气地提醒；
- 死亡时给出审判报告；
- 通关时给出带一点不信任的评价。

系统语气示例：

```text
旧模式已识别：你又开始解释自己了。

系统提示：这不是沟通，这是把对方拖回你的证明现场。

隐藏判定触发：你前面已经连续两次把 TA 的感受转回自己身上。
```

### 4.3 Boss 身份

每个人格不是“真实的人”，而是该人格的互联网刻板印象 Boss。

例如：

- INFJ：终极门锁；
- INTJ：冷静审判者；
- INFP：破碎理想家；
- ENTP：辩论恶魔。

Boss 不是为了准确，而是为了“像”和“好玩”。

## 5. 剧本结构

### 5.1 每个副本至少 5 关

MVP 可以先 4 关，但正式版本建议每个副本 5-7 关。

推荐标准结构：

| 关卡 | 剧情功能 | 玩家体验 |
|---|---|---|
| 第 1 关 | 关系已经出问题，给一个低门槛场景 | 快速代入，容易死 |
| 第 2 关 | TA 开始表达真实感受或真实逻辑 | 玩家开始紧张 |
| 第 3 关 | 前面选择开始被系统记住 | 产生“它真的在看我”的感觉 |
| 第 4 关 | 人格核心雷点出现 | 副本差异感拉开 |
| 第 5 关 | 最终考验 | 生成结局或隐藏结局 |
| 第 6-7 关 | 可选高级关卡 | 给重度用户二刷空间 |

### 5.2 每一关不是独立题

每一关都要接住上一关的状态。

错误示例：

```text
第 1 关：TA 说没事。
第 2 关：TA 问你周末去哪。
第 3 关：TA 说自己累。
```

问题：像随机题库。

正确示例：

```text
第 1 关：TA 说没事，你选择了解释自己。
第 2 关：系统提示“解释倾向 +1”，TA 的回复变得更短。
第 3 关：TA 说“我不想再听你解释”，因为前面的选择已经改变了对话气氛。
```

## 6. 选择后应该发生什么

### 6.1 不是只有对错

每个选项应该同时承担三个功能：

1. 推进剧情；
2. 暴露用户模式；
3. 修改隐藏变量。

每个选项都应该有一个“行为标签”。

例如：

```ts
{
  id: 'B',
  text: '我真的不是那个意思，你听我解释。',
  isCorrect: false,
  pattern: 'self_proof',
  pressure: 2,
  empathy: -1,
  deathTitle: '解释成瘾'
}
```

### 6.2 选择后反馈分三层

用户选择后，不要只弹一个解释。

应该分三层：

#### 第一层：即时反应

TA 对这句话的即时反应。

```text
TA 沉默了 12 秒。
对话框上方的“正在输入”出现又消失。
```

#### 第二层：系统识别

系统识别用户的行为模式。

```text
系统识别：证明欲 +1
旧模式提示：你又把重点放回自己身上了。
```

#### 第三层：剧情影响

这次选择如何影响后续。

```text
后续影响：TA 的信任值降低，下一关将触发“旧账回流”。
```

### 6.3 错误不一定马上死亡

正式版本不建议所有错误都立即死亡。

应该有三种结果：

| 结果 | 说明 |
|---|---|
| 立即死亡 | 选项踩中人格核心雷点 |
| 扣血继续 | 选项不够好，但还能补救 |
| 隐藏污染 | 表面过关，但埋下后续死亡条件 |

例如 INFJ：

- “你是不是又冷暴力？”可以立即死亡；
- “我不是那个意思，你听我解释”可以扣血继续；
- “那你冷静吧”可以埋下冷处理污染，后面触发死亡。

这样会比单纯答题复杂，也更有趣。

## 7. 隐藏变量系统

### 7.1 全局变量

每个副本都可以共享一套基础变量：

```ts
interface PlayerState {
  empathy: number;       // 共情值
  pressure: number;      // 压迫感
  selfProof: number;     // 证明欲
  control: number;       // 控制欲
  avoidance: number;     // 回避倾向
  logic: number;         // 逻辑化倾向
  playfulness: number;   // 轻松感
  trust: number;         // 信任值
  damage: number;        // 关系损伤
  flags: string[];       // 隐藏标记
}
```

### 7.2 人格专属变量

不同人格还要有自己的专属变量。

#### INFJ

```ts
interface InfjState extends PlayerState {
  emotionalSafety: number;   // 情绪安全
  oldPatternDetected: number; // 旧模式识别
  boundaryRespect: number;   // 边界尊重
}
```

核心判断：

- 情绪安全低：死亡；
- 旧模式识别过高：触发“不是这句话，是熟悉的模式”；
- 边界尊重低：触发“你把空间变成惩罚”。

#### INTJ

```ts
interface IntjState extends PlayerState {
  credibility: number;     // 可信度
  planClarity: number;     // 方案清晰度
  emotionalNoise: number;  // 情绪噪音
}
```

核心判断：

- 可信度低：死亡；
- 情绪噪音高：防火墙升级；
- 方案清晰度高：进入观察期。

#### INFP

```ts
interface InfpState extends PlayerState {
  dreamIntegrity: number;   // 旧梦完整度
  meaningRespect: number;   // 意义感尊重
  tenderness: number;       // 温柔值
}
```

核心判断：

- 旧梦完整度低：滤镜破碎死亡；
- 意义感尊重低：触发“现实铁锤”；
- 温柔值高：进入慢修复结局。

#### ENTP

```ts
interface EntpState extends PlayerState {
  banterSync: number;       // 玩笑同步
  debateTrap: number;       // 辩论陷阱
  selfStability: number;    // 自我稳定
}
```

核心判断：

- 辩论陷阱高：被反杀；
- 玩笑同步高：进入轻松修复线；
- 自我稳定低：被激将带崩。

## 8. 题目数据结构升级

当前项目的题目结构可以跑 MVP，但后续需要升级。

建议从单纯 `isCorrect` 升级为：

```ts
export interface ChallengeOption {
  id: 'A' | 'B' | 'C' | 'D';
  text: string;

  // 结果类型
  outcome: 'death' | 'survive' | 'damage' | 'hidden';

  // 行为模式标签
  pattern: 'self_proof' | 'pressure' | 'empathy' | 'avoidance' | 'control' | 'logic' | 'playful';

  // 变量变化
  effects: Partial<PlayerState>;

  // 即时演出
  targetReaction: string;
  systemComment: string;

  // 死亡内容
  deathTitle?: string;
  deathReport?: string;
  deathRate?: string;

  // 后续剧情标记
  addFlags?: string[];
  requireFlags?: string[];
  blockFlags?: string[];
}
```

### 8.1 题目也要支持条件分支

```ts
export interface ChallengeQuestion {
  id: string;
  level: number;
  title: string;
  scene: string;
  messages: ChatMessage[];
  question: string;
  options: ChallengeOption[];

  // 根据前面选择改变题目
  variants?: Array<{
    whenFlags: string[];
    scene?: string;
    messages?: ChatMessage[];
    question?: string;
  }>;
}
```

这样就可以实现：

```text
如果玩家前面多次解释自己，第 3 关 TA 会说：
“你看，你现在又开始解释了。”

如果玩家前面尊重边界，第 3 关 TA 会说：
“谢谢你刚才没有一直追问。”
```

这就是有心意的细节。

## 9. 分支复杂度控制

不要一开始做成真正的超大文字冒险，那会爆炸。

推荐使用“轻分支，重反馈”。

### 9.1 不建议

```text
第 1 关 4 个选择
每个选择进入完全不同的第 2 关
第 2 关再分 4 条
最后变成 4^5 条剧情
```

这样写不完，也不好维护。

### 9.2 建议

主线保持一条，但每关根据状态产生不同反馈。

```text
主线关卡固定：1 → 2 → 3 → 4 → 5

变化发生在：
- TA 的一句补充台词；
- 系统提示；
- 选项是否变危险；
- 死亡报告标题；
- 最终结局类型。
```

这叫：

> 轻分支，重记忆。

用户会觉得系统记住了他，但内容生产量不会失控。

## 10. 副本标准剧本模板

每个人格副本都按下面模板写。

### 10.1 副本封面

```text
人格：INFJ
副本名：挽回 INFJ 挑战
Boss 名：终极门锁
副本简介：TA 不是突然离开，是早就在心里告别过很多次。
核心雷点：解释、逼问、冷处理、否认旧伤
核心通关方式：接住感受、尊重边界、承认旧模式、稳定行动
```

### 10.2 副本剧情大纲

```text
开场：关系已经变冷，TA 表面平静。
第 1 关：TA 说没事。
第 2 关：TA 终于讲一点感受。
第 3 关：TA 要空间。
第 4 关：TA 提到旧伤。
第 5 关：TA 问“这次有什么不一样”。
结局：
- 死亡：旧模式复发；
- 残血：TA 没有回来，但没有彻底关门；
- 通关：获得观察期；
- 隐藏：TA 承认“这次我感觉你真的听见了”。
```

### 10.3 每关写作模板

```text
关卡名：
剧情位置：
TA 当前心理：
用户最容易犯的错：
正确方向：
四个选项：
A：核心雷点，可能死亡
B：常见错误，扣血
C：最佳选择，继续
D：伪正确选择，埋隐藏污染
选择后 TA 的反应：
系统识别：
后续影响：
死亡报告：
```

## 11. 四个首发副本定调

### 11.1 INFJ：挽回 INFJ 挑战

#### 核心体验

玩家以为自己在解释，其实一直在证明自己。

#### 副本味道

- 安静；
- 深；
- 有旧伤；
- 不直接爆炸；
- 死亡报告很刺。

#### 玩家常见死亡方式

- 解释成瘾；
- 情绪逼供；
- 伪尊重；
- 冷处理反噬；
- 旧账羞辱；
- 安全感勒索。

#### 通关不是复合

INFJ 的通关不应该是“TA 回来了”。

更合适的是：

> TA 没有立刻回来，但门没有继续关上。

### 11.2 INTJ：破解 INTJ 防火墙

#### 核心体验

玩家以为情绪能打动 TA，其实 TA 在看风险、证据和可持续性。

#### 副本味道

- 冷；
- 硬；
- 像审批；
- 像系统权限；
- 反馈像审查报告。

#### 玩家常见死亡方式

- 情绪攻击无效；
- 依赖警报；
- 机会勒索；
- 方案不闭环；
- 口头承诺过载。

#### 通关不是心软

INTJ 的通关应该是：

> 你获得了观察期，不是原谅。

### 11.3 INFP：修复 INFP 旧梦

#### 核心体验

玩家以为问题是一次争吵，其实是 TA 对这段关系的想象碎了。

#### 副本味道

- 柔软；
- 破碎；
- 理想感；
- 回忆杀；
- 死亡报告像一把很轻的刀。

#### 玩家常见死亡方式

- 否认坍塌；
- 现实铁锤；
- 道歉索赔；
- 回忆驱逐；
- 强行翻篇。

#### 通关不是哄好

INFP 的通关应该是：

> 旧梦没有完全复原，但它不再继续碎下去。

### 11.4 ENTP：别被 ENTP 反杀

#### 核心体验

玩家以为自己在沟通，其实已经被拖进辩论场。

#### 副本味道

- 快；
- 损；
- 轻松；
- 反问多；
- 死亡报告要好笑。

#### 玩家常见死亡方式

- 玩笑识别失败；
- 防御性开局；
- 互相甩锅；
- 被审判感破防；
- 自尊爆雷；
- 经典废话。

#### 通关不是吵赢

ENTP 的通关应该是：

> 你没有赢辩论，但你保住了互动感。

## 12. 结局系统

每个副本至少有 4 类结局。

### 12.1 即死结局

踩中核心雷点，直接死亡。

例：

```text
你死于第 1 关：情绪逼供。
你把 TA 的沉默翻译成审判，又把自己的不安递成考卷。
```

### 12.2 残血结局

没有死，但状态很差。

例：

```text
你活到了最后，但系统并不看好。
TA 没有把门关死，只是暂时没再继续后退。
```

### 12.3 普通通关

做到了基本正确。

例：

```text
你没有让旧模式彻底复发。
系统判定：获得观察期。
```

### 12.4 隐藏通关

前面多次选择高质量选项，触发隐藏结局。

例：

```text
隐藏结局：TA 说“这次我感觉你真的听见了。”
系统提示：这不是复合成功，这是旧循环第一次被中断。
```

## 13. “有心意”的细节清单

### 13.1 UI 细节

- TA 输入中出现又消失；
- 选错后屏幕轻微闪红；
- 死亡报告像系统档案；
- 每个人格有专属背景和图标；
- 结果页有“系统识别出的旧模式”；
- 重复挑战时显示“旧档案已载入”。

### 13.2 文案细节

- 不说“你错了”，说“旧模式已识别”；
- 不说“回答错误”，说“死亡条件触发”；
- 不说“正确答案”，说“暂时存活”；
- 不说“通关成功”，说“获得观察期”；
- 不说“再试一次”，说“重开副本”。

### 13.3 玩法细节

- 连续两次选择解释型选项，后面触发“解释成瘾”专属死亡；
- 连续两次选择冷处理，后面触发“惩罚性撤退”；
- 高共情低行动，触发“温柔但无交付”；
- 高逻辑低共情，在 INTJ 是加分，在 INFJ/INFP 可能扣分；
- 高玩笑感在 ENTP 是加分，在 INFJ 可能被判定为轻飘飘跳过。

这会让每个人格真正不同。

## 14. 技术实现策略

### 14.1 MVP 现状

当前仓库已经是：

```text
固定关卡 + 单选项正确/错误 + 错误立即死亡 + 通关结果
```

这是第一层骨架。

### 14.2 下一步升级目标

升级成：

```text
固定主线 + 状态变量 + 选项影响 + 条件反馈 + 多结局
```

### 14.3 推荐分三步实现

#### 第一步：扩展数据结构

加入：

- outcome；
- pattern；
- effects；
- targetReaction；
- systemComment；
- flags。

#### 第二步：增加玩家状态

在 App 或 store 中保存 `PlayerState`。

每次选择后更新状态。

#### 第三步：增加条件文案

根据 flags 和变量，改变：

- 下一关场景；
- TA 的一句台词；
- 系统提示；
- 最终结局。

## 15. 内容生产流程

之后每做一个新人格，不要直接写题库。

先写这 5 个东西：

1. 人格 Boss 卡；
2. 副本剧情大纲；
3. 核心雷点列表；

## 17. 最终原则

这个项目最重要的不是题目数量，而是用户玩完后的感觉。

用户应该觉得：

```text
它不一定科学，但它很懂这个梗。
它不一定真的有用，但它真的很好玩。

它不是单纯骂我，它骂得有点准。
```

> 做一个让人愿意截图、转发、拉朋友来死一遍的人格副本网站。
